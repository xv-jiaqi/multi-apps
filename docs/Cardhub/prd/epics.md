# 史诗 (Epics)

## 5.1 史诗 1：技术基石与核心浏览体验

- **目标：** 建立项目的技术基础（包括前后端骨架、数据库连接、Monorepo仓库），并交付核心的只读用户体验，让用户能看到卡牌和系列介绍页面。

### 用户故事 1.1：项目与 Monorepo 仓库设置

- **作为** 一名开发者，
- **我想要** 一个配置好的、包含 PNPM 和 Turborepo 的 Monorepo 仓库，
- **以便于** 我可以在一个地方统一管理前端和后端的代码。
- **验收标准：**
  1.  一个新的 GitHub 私有仓库已创建。
  2.  仓库已使用 PNPM Workspaces 和 Turborepo 正确初始化。
  3.  仓库根目录包含基础的 `README.md` 和 `.gitignore` 文件。

### 用户故事 1.2：前端应用骨架创建

- **作为** 一名开发者，
- **我想要** 一个使用 Vite 创建的基础 React 应用，
- **以便于** 我有了一个可以立即开始开发的前端项目起点。
- **验收标准：**
  1.  在 Monorepo 的 `apps/web` 目录下，已使用 Vite 创建了一个新的 React + TypeScript 项目。
  2.  项目中已安装并基础配置了 TailwindCSS 和 shadcn/ui。
  3.  在项目根目录运行 `pnpm dev` 命令后，前端应用可以成功启动。
  4.  浏览器访问应用时，能看到一个包含"欢迎来到 Cardhub"字样的简单首页。

### 用户故事 1.3：后端服务骨架创建

- **作为** 一名开发者，
- **我想要** 一个基础的 Rust 后端服务骨架，
- **以便于** 我有了一个可以立即开始开发 API 的后端项目起点。
- **验收标准：**
  1.  在 Monorepo 的 `apps/server` 目录下，已创建了一个新的 Rust Web 服务项目（使用 Axum 框架）。
  2.  后端服务可以成功编译并运行。
  3.  服务对外暴露一个 `/health` 健康检查接口，访问该接口会返回 `{"status": "ok"}` 的 JSON 响应。

### 用户故事 1.4：静态系列介绍页

- **作为** 一名用户，
- **我想要** 访问一个关于卡牌系列的介绍页面，
- **以便于** 我可以了解到这个系列的背景信息和包含的卡牌列表。
- **验收标准：**
  1.  在 React 应用中创建了新的页面路由（例如 `/series/[seriesSlug]`）。
  2.  该页面能够展示一个系列的硬编码（Hardcoded）模拟数据，包括系列标题、描述和一个简单的卡牌名称列表。
  3.  页面布局整洁，并遵循了 shadcn/ui 的基础样式。

### 用户故事 1.5：静态卡牌详情页

- **作为** 一名用户，
- **我想要** 访问一个单张卡牌的详情页面，
- **以便于** 我可以查阅这张卡的详细数据。
- **验收标准：**
  1.  在 React 应用中创建了新的页面路由（例如 `/cards/[cardSlug]`）。
  2.  该页面能够展示单张卡牌的硬编码模拟数据，包括卡牌名称、图片、描述和属性。
  3.  页面布局清晰易读，并为未来的"评论区"留下一个占位符。

## 5.2 史诗 2：数据库集成与搜索功能

- **目标：** 将前端与真实的后端数据库打通，实现动态数据显示，并上线核心的卡牌搜索功能。

### 用户故事 2.1：数据库表结构定义与连接

- **作为** 一名开发者，
- **我想要** 定义好 PostgreSQL 的数据库表结构，并让 Rust 后端服务能成功连接到数据库，
- **以便于** 我们能为存储和读取真实的卡牌数据做好准备。
- **验收标准：**
  1.  已创建 SQL 脚本，用于定义所有核心数据表。
  2.  Rust 后端应用已配置好数据库连接信息。
  3.  后端服务在启动时能够成功连接到 PostgreSQL 数据库。
  4.  已在后端项目中建立基础的数据访问层（使用 `SQLx` 或 `Diesel`）。

### 用户故事 2.2：后端核心数据接口开发

- **作为** 一名开发者，
- **我想要** 创建后端 API 接口，用于获取系列列表、系列详情和卡牌详情，
- **以便于** 前端应用有动态数据的来源。
- **验收标准：**
  1.  已创建 `GET /api/series` 接口，用于返回所有卡牌系列的列表。
  2.  已创建 `GET /series/{slug}` 接口，用于返回单个系列的详细信息及其包含的卡牌列表。
  3.  已创建 `GET /cards/{slug}` 接口，用于返回单张卡牌的详细信息。
  4.  接口返回统一的 JSON 格式，并包含基础的错误处理（如 404 Not Found）。

### 用户故事 2.3：前端动态数据接入

- **作为** 一名开发者，
- **我想要** 将前端页面中的静态模拟数据，替换为从后端 API 获取的动态数据，
- **以便于** 应用能够展示真实、准确的信息。
- **验收标准：**
  1.  前端应用使用 SWR 库来请求后端的 API 接口。
  2.  系列详情页和卡牌详情页现在展示的是从对应 API 获取的动态数据。
  3.  数据加载（Loading）和加载错误（Error）的状态在界面上有清晰、友好的展示。

### 用户故事 2.4：后端搜索接口开发

- **作为** 一名开发者，
- **我想要** 创建一个后端 API 接口，允许根据卡牌名称进行搜索，
- **以便于** 为前端的搜索功能提供支持。
- **验收标准：**
  1.  已创建 `GET /api/search/cards?q=<query>` 接口。
  2.  接口能根据 `q` 参数，返回卡牌名称模糊匹配的卡牌列表。
  3.  搜索功能不区分大小写，并支持多语言名称。
  4.  接口已通过数据库索引等方式进行了基础的性能优化。

### 用户故事 2.5：前端搜索功能实现

- **作为** 一名用户，
- **我想要** 使用一个搜索框按名称查找卡牌，
- **以便于** 我可以快速定位到我感兴趣的特定卡牌。
- **验收标准：**
  1.  在应用的醒目位置增加了一个搜索框组件。
  2.  用户输入时，应用会（通过防抖/Debounce机制）调用后端搜索接口获取结果。
  3.  搜索结果会实时展示在下拉列表或独立的搜索结果页面中。
  4.  点击任一搜索结果，会跳转到该卡牌的详情页面。

## 5.3 史诗 3：用户系统与社区互动

- **目标：** 构建一个基础的用户认证系统，并在此之上实现 MVP 最核心的社区功能——卡牌详情页的评论与交流。

### 用户故事 3.1：用户认证页面的 UI 构建

- **作为** 一名新用户，
- **我想要** 看到一个注册和登录的页面，
- **以便于** 我可以创建账户或登录。
- **验收标准：**
  1.  已创建 `/register` 注册页面和 `/login` 登录页面。
  2.  页面 UI 使用 shadcn/ui 组件构建。
  3.  输入框包含基础的前端格式校验。

### 用户故事 3.2：后端用户认证接口开发

- **作为** 一名开发者，
- **我想要** 创建用于用户注册和登录的后端 API 接口，
- **以便于** 前端有验证用户身份的方式。
- **验收标准：**
  1.  数据库中已创建 `users` 表。
  2.  已在 Rust 后端创建 `POST /api/auth/register` 接口。
  3.  已在 Rust 后端创建 `POST /api/auth/login` 接口，成功后返回 JWT。
  4.  接口包含对"用户已存在"或"凭据无效"等场景的错误处理。

### 用户故事 3.3：前端认证逻辑实现

- **作为** 一名用户，
- **我想要** 能通过界面成功注册账户并登录，
- **以便于** 我可以使用需要登录后才能访问的功能。
- **验收标准：**
  1.  注册和登录页面的表单现在可以调用后端的对应 API 接口。
  2.  用户成功登录后，JWT 会被安全地存储在客户端。
  3.  应用界面会更新以显示"已登录"状态。

### 用户故事 3.4：后端评论功能接口开发

- **作为** 一名开发者，
- **我想要** 创建用于发布和读取卡牌评论的后端 API 接口，
- **以便于** 用户可以进行讨论。
- **验收标准：**
  1.  数据库中已创建 `comments` 表。
  2.  已创建一个受保护的 `POST /cards/{cardId}/comments` 接口，只允许已认证的用户发布新评论。
  3.  `GET /cards/{cardId}/comments` 接口的返回数据中，现在包含了与该卡牌关联的所有评论列表。

### 用户故事 3.5：前端评论功能实现

- **作为** 一名已登录的用户，
- **我想要** 在卡牌详情页发布评论，并看到其他人的评论，
- **以便于** 我可以参与社区讨论。
- **验收标准：**
  1.  在卡牌详情页，当用户处于登录状态时，会显示一个用于提交新评论的表单。
  2.  提交表单后，新评论会出现在评论列表中。
  3.  未登录的用户可以查看评论，但看不到评论发布表单。
