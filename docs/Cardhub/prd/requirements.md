# 需求 (Requirements)

## 2.1 功能性需求 (Functional Requirements)

- **FR1:** 系统必须提供一个可供浏览和搜索的卡牌数据库。
- **FR2:** 系统必须为不同的卡牌系列提供图文并茂的介绍页面。
- **FR3:** 用户必须能够创建和登录自己的账户。
- **FR4:** 登录用户必须能够在卡牌和系列介绍页面下发表、查看评论。

## 2.2 非功能性需求 (Non-Functional Requirements)

- **NFR1:** MVP 必须是一个响应式的 Web 应用程序，在主流桌面和移动浏览器上都能提供良好的用户体验。
- **NFR2:** 系统必须从架构层面支持多语言国际化，以便未来扩展。
- **NFR3:** 系统必须保证高性能，核心页面的加载和数据库的搜索响应应快速、流畅。
- **NFR4:** 系统的界面和交互设计必须对新手用户友好，做到简单、直观、易于上手。
- **NFR5:** 系统必须遵循我们已确定的技术栈（前端 React, 后端 Rust, 数据库 PostgreSQL 等）。
- **NFR6:** 系统必须符合 WCAG 2.1 AA 无障碍设计标准。
