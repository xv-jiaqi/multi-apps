> 上级文档：[../README.md](../README.md)。owner 授权由方案作者拍板，所以本文没有“待决问题”：每一项都是**已定的决策**，实现时照做，不要停下来等确认。要推翻某条决策，先改本文，再改受影响的分册。编号只增不改，其他文档按编号引用（如“见 D12”）。

## 1. 决策

### 1.1 平台与进程

| 编号 | 决策                                                                                                                                                                                                                                        | 理由                                                                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| D1   | 只支持 **macOS 14 及以上**，以 Apple Silicon 为准（Intel 不测试）。只在 owner 自己的开发电脑上运行，单用户。                                                                                                                                | Bot 面板的独立 Cookie 存储（`data_store_identifier`）需要 macOS 14；运行环境唯一，不做兼容层。                      |
| D2   | 桌面壳用 **Tauri v2.12**（Cargo 特性 `unstable`、`tray-icon`）。Rust 代码只有 `desktop/src-tauri/src/lib.rs` 一个业务文件（约 480 行），[desktop-shell.md](desktop-shell.md) 给出**已编译通过的全文**，实现时原样复制，不在 Rust 里加功能。 | owner 不熟悉 Rust；多 WebView、导航拦截、侧车进程管理这几件事必须在原生层做，其余全部放到 TypeScript。              |
| D3   | 桌面逻辑能用 Tauri 的 JS API 做的都在 TS 里做：Bot 面板的位置与显隐、应用菜单与快捷键、菜单栏图标标题、系统通知、侧车崩溃后的重启退避、外链与“在 Finder 中显示”。代码在 `web/src/desktop/`。                                                | 同 D2。                                                                                                             |
| D4   | 全部业务逻辑在 **Node 侧车** `@agent-hub/server`（NestJS 11 + `ws`）里，由 Rust 壳用本机的 Node（≥ 22.13）拉起。                                                                                                                            | 协议生态（Codex 生成类型、ACP 类型）在 TS；能在 CI 里用 jest 测；与 `apps/cardhub/api` 同栈。                       |
| D5   | v1 **不做自包含打包**：`.app` 通过编译期常量找到源码检出目录里的 `server/dist/main.js`；环境变量 `AGENT_HUB_SERVER_ENTRY` 可覆盖。                                                                                                          | 只在 owner 自己的电脑上用；省掉把 Node 和依赖打进 `.app` 的工作。代价：移动源码目录后要重新 `pnpm desktop:bundle`。 |
| D6   | Node 的查找顺序：`AGENT_HUB_NODE` → 登录 shell 里的 `command -v node` → `/opt/homebrew/bin/node` → `/usr/local/bin/node`。侧车启动时自检版本，低于 22.13 直接 `fatal`（`NODE_TOO_OLD`）。                                                   | 从 Finder 启动的应用只有最小 PATH；22.13 起 `node:sqlite` 不需要命令行开关。                                        |
| D7   | 侧车以 `--lifeline stdin` 启动：**stdin 读到 EOF 就优雅停机**。Rust 退出时先关 stdin，等 10 秒再强杀。独立运行（不带该参数）时只响应 SIGINT / SIGTERM。                                                                                     | 壳崩溃时 stdin 自动关闭，侧车不会变成孤儿；终端里手动运行时不会因为 stdin 被关而退出。                              |
| D8   | 侧车 stdout **只输出协议行**：一行 `{"event":"ready",...}` 或一行 `{"event":"fatal",...}`；其余输出走 stderr 和日志文件。                                                                                                                   | Rust 按行解析，不能混入日志。                                                                                       |
| D9   | **UI token** 每次侧车启动随机生成（32 字节），只经 ready 行交给 Rust，再由 `sidecar_start` 返回给 Hub UI；不落盘。浏览器开发模式下侧车在 stderr 打印 `http://localhost:5174/#uiToken=…` 链接。                                              | token 不在磁盘上；开发时也不用手抄。                                                                                |
| D10  | 端口默认 **47821**，`config.json` 的 `server.port` 可改。端口被占用时侧车 `fatal`（`PORT_IN_USE`），**不换端口、不结束别的进程**。只监听 `127.0.0.1`。                                                                                      | 本地郎写死端口最省事；自动换端口会让桥接方找不到 Hub。                                                              |
| D11  | 关闭主窗口 = 隐藏，侧车和任务继续运行；真正退出走菜单“退出 Agent Hub”（⌘Q，有进行中任务时二次确认）。                                                                                                                                       | 本地郎派来的任务不能因为关窗口而中断。                                                                              |
| D12  | 打包只出 `.app`（`tauri build --bundles app`），ad-hoc 签名（`signingIdentity: "-"`），不公证、不做自动更新。                                                                                                                               | 自用；公证需要开发者账号。                                                                                          |

### 1.2 数据与配置

| 编号 | 决策                                                                                                                                                                                                                                                                                   | 理由                                                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| D13  | 数据**只存本机**，用 Node 内置的 **`node:sqlite`**（`DatabaseSync`）。不用 Prisma、不用 better-sqlite3，没有远端持久化、没有同步、没有遥测。                                                                                                                                           | 零原生依赖、不需要 `onlyBuiltDependencies`；不受 nvm 切换 Node 版本导致的原生模块 ABI 不匹配影响；已实测 Node 22.23 + jest 30 可用。 |
| D14  | 一个库文件 `hub.db`（WAL 模式）。diff 补丁存在库里；协议原始帧（transcript）默认**不录**，打开诊断开关后才写 `transcripts/<taskId>.ndjson`；日志写 `logs/`。                                                                                                                           | 备份只拷一个文件；transcript 只在排障和录制测试夹具时有用。                                                                          |
| D15  | **用户设置全部放 `config.json`**：Agent 配置、仓库、Bot 面板、安全、保留期限、诊断开关。数据库只放运行数据：任务、轮、事件、审批、桥接 token、幂等键、审计、子进程记录。                                                                                                               | 设置可以手改、可以整体备份；不出现“库里一份、配置里一份”。                                                                           |
| D16  | 数据库迁移是手写 SQL 数组，`PRAGMA user_version` 记版本，只追加不修改。                                                                                                                                                                                                                | 没有 ORM，迁移最简单的做法。                                                                                                         |
| D17  | 保留期限（`config.json` 的 `retention` 可改）：增量事件在任务结束 **30 天**后删除（状态、轮次、审批、diff、提示等非增量事件一直保留）；transcript **14 天**；归档满 **30 天**后移除 worktree（分支保留）；审计 **180 天**；日志 **14 天**。任务、轮、diff 补丁保留到用户删除任务为止。 | 增量事件占大头；结论性数据要能回看。                                                                                                 |
| D18  | 数据目录 `AGENT_HUB_HOME`，默认 `~/Library/Application Support/AgentHub`，环境变量可覆盖（测试一律指向临时目录）。                                                                                                                                                                     | macOS 惯例。                                                                                                                         |
| D19  | 任务 id 用 `crypto.randomUUID()`；另有 8 位十六进制的 `shortId`（取 UUID 去掉连字符后的前 8 位，撞了就重新生成），用在分支名 `agent-hub/<shortId>` 和界面上。                                                                                                                          | 不引入 ULID 依赖；分支名要短。                                                                                                       |
| D20  | 每个任务必须属于一个已注册的仓库（`repoId`）。桥接方不传 `repoId` 时用 `config.json` 的 `defaultRepoId`；没有默认仓库就返回 `VALIDATION_FAILED`。                                                                                                                                      | 所有 Agent 都需要工作目录；“这个仓库”是本地郎最常见的语境。                                                                          |

### 1.3 界面与接口

| 编号 | 决策                                                                                                                                                                                                                                                                            | 理由                                                                          |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| D21  | Hub UI：**Vite 8 + React 19 + Tailwind CSS 4 + `@repo/ui-web`**。服务端状态用 **TanStack Query 5**，WebSocket 收到的事件直接写进 Query 缓存；本地界面状态用 React state 和少量 Context，**不用 MobX**（偏离仓库约定）。                                                         | 界面上几乎所有状态都来自侧车；再加一层 store 只会制造同步问题。               |
| D22  | 路由用 React Router 7 的 `createHashRouter`。                                                                                                                                                                                                                                   | Tauri 自定义协议下不依赖服务器的 SPA 回退。                                   |
| D23  | **Hub UI 与本地郎共用同一套 REST + WebSocket 接口 `/api/v1`**，不用 tRPC（偏离仓库约定）。请求体与 DTO 的 zod schema 在 `@agent-hub/contract`，Hub UI 用一个手写的类型化 `fetch` 封装。管理类接口（设置、token、删除、应用改动）只认 UI token。                                 | 一套契约、一套鉴权、一套测试；本地郎需要语言无关的接口，tRPC 只能多出第二套。 |
| D24  | 界面只做简体中文，不接 i18n。                                                                                                                                                                                                                                                   | 自用。                                                                        |
| D25  | 不支持附件（图片、文件），提示词只有文本。                                                                                                                                                                                                                                      | 缩小 v1 范围；三类 Agent 的附件语义各不相同。                                 |
| D26  | 追问时可以改模型和推理档位（Codex 每轮 `turn/start` 都能带；ACP 每轮发提示词前用 `session/set_config_option` 对齐，Agent 只有旧 `models` 字段时用 `session/set_model`，[adapter-acp.md](adapter-acp.md) §4.5）。不提供“会话模式”选择，模式由 Hub 按只读 / 可写自动设置（D37）。 | 改模型是常见需求；会话模式与安全边界绑定，不交给用户随手改。                  |
| D27  | 不集成 Sentry 或任何外部遥测；日志只落本机。日志用自写的 JSON 行文件写入器（按天一个文件），Nest 的 `Logger` 接到它上面，不引入 pino。                                                                                                                                          | 提示词和代码是公司资产；依赖越少越好。                                        |
| D28  | 菜单栏图标只用来显示主窗口，图标旁的标题显示待审批数（为 0 时不显示），没有托盘菜单。系统通知三类：有新审批、任务结束、网页任务的提示词已就绪（等人去 AoneD 里操作，[web-agent.md](web-agent.md) §5.2）；只在主窗口不在前台时发。                                               | 够用即可。                                                                    |
| D29  | 本地郎的对话页 URL **没有默认值**；首次启动时左栏显示“设置本地郎地址”的引导。                                                                                                                                                                                                   | 文档与代码里不出现真实内网地址。                                              |

### 1.4 Agent 接入

| 编号 | 决策                                                                                                                                                                                                                                                                                                                                                                                                                          | 理由                                                                                                                                                                                                                    |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D30  | Codex：每个 Codex 配置**共享一个** `codex app-server` 进程，每个任务一个 thread。`approvalPolicy: "on-request"`；只读任务沙箱 `read-only`，可写任务 `workspace-write`；每轮都显式传 `networkAccess: false`。                                                                                                                                                                                                                  | app-server 本身按 thread 多路复用；省冷启动。网络关掉是推送守卫的一部分（[security.md](security.md) §3）。                                                                                                              |
| D31  | Codex 的 `threadSource: "user"` **默认发送**（任务字段 `userVisible` 默认 `true`，新建任务时可关）。不做能力探测门槛。                                                                                                                                                                                                                                                                                                        | 0.164 协议里有这个字段；即使 ChatGPT 应用不显示，代价也只是“只能在 Hub 里看”。                                                                                                                                          |
| D32  | Codex 每次建 thread 前先调 `account/read`：`account` 为 `null` 且 `requiresOpenaiAuth` 为 `true` 时任务直接失败（`AGENT_AUTH_REQUIRED`），不建 thread。                                                                                                                                                                                                                                                                       | 实测未登录时 thread 能建成功，要等 5 次重连后才失败，体验很差。                                                                                                                                                         |
| D33  | Codex 协议类型**手写**在 `server/src/adapters/codex/protocol.ts`（只含用到的子集，按 0.164.0 核对），不在 CI 里运行 `codex app-server generate-ts`。                                                                                                                                                                                                                                                                          | CI 里没有 Codex；生成物有 600 多个文件。                                                                                                                                                                                |
| D34  | ACP：**协议客户端自己实现**，与 Codex 共用同一个 JSON-RPC 行传输；`@agentclientprotocol/sdk` 只用 `import type` 取类型。                                                                                                                                                                                                                                                                                                      | SDK 2.0.2 是纯 ESM 包，侧车与 jest 都是 CommonJS；客户端一侧只有十来个方法，自己写比处理 ESM 互操作简单。                                                                                                               |
| D35  | ACP 每个任务一个进程（独立进程组）。任务进入终态后进程**闲置 10 分钟**结束。之后追问按新进程 `initialize` 声明的能力恢复：声明了 `sessionCapabilities.resume` 用 `session/resume`，只声明 `loadSession` 用 `session/load`（回放的历史全部丢弃），失败时**不**改试另一种；两者都没声明时该轮失败，错误码 `SESSION_NOT_RESUMABLE`（[adapter-acp.md](adapter-acp.md) §9）。                                                      | ACP 实现参差不齐，按进程组结束最干净；`resume` 说会话不存在时 `load` 也不会成功。                                                                                                                                       |
| D36  | ACP 客户端能力：`fs.readTextFile: false`、`fs.writeTextFile: false`、`terminal: false`，只声明 `session.notices`（Agent 才会发 `notice`）。Agent 发来 `fs/*`、`terminal/*` 等请求时回 `-32601`。Agent 用自己的工具读写文件、执行命令。                                                                                                                                                                                        | Hub 代为读写或执行，等于 Hub 自己要做沙箱和路径校验。                                                                                                                                                                   |
| D37  | ACP 会话模式按 profile 设置并守住（[adapter-acp.md](adapter-acp.md) §3、§5）。目标模式：只读任务依次取 `plan`、`default` 里 Agent 提供的第一个（Qoder 只有 `default` 可用），可写任务取 `default`；每个会话建好后都**显式切过去**。允许的模式：只读任务只有目标模式；可写任务另外允许只读模式。Agent 中途切到不允许的模式（`acceptEdits`、`auto`、`bypassPermissions`、`yolo` 等）时，Hub 立即切回并发 `MODE_RESTORED` 提示。 | 没有沙箱时只读靠模式加审批，跳过审批的模式会让审批失效；Qoder、Gemini 的默认模式可以被用户在 Agent 自己的设置里改成 `yolo`，所以不能“用 Agent 默认”。                                                                   |
| D38  | 没有沙箱的 ACP Agent 做只读任务时，“只读”靠**审批 + 轮后树快照比对**保证；新建任务对话框在这种组合下显示提示。                                                                                                                                                                                                                                                                                                                | Hub 无法替 Qoder 加沙箱；如实告知。                                                                                                                                                                                     |
| D39  | 预置 Agent 配置：`codex`（启用）、`qoder`（启用）、`claude-code`（`claude-agent-acp`，默认禁用）、`gemini`（`gemini --acp`，默认禁用）、`aoned`（网页，默认禁用）。                                                                                                                                                                                                                                                           | 前两个是 owner 正在用的；其余以配置方式就绪。                                                                                                                                                                           |
| D40  | **网页 Agent（AoneD）v1 是人工协作驱动**：Hub 建任务分支并推到内网 `internal`，给出提示词和打开链接；人在浏览器里操作 AoneD；Hub 轮询远端分支、拉取并算 diff；人点“完成本轮”。**不做页面自动化，不引入 Playwright。** 自动化驱动作为扩展点保留（[web-agent.md](web-agent.md) §7）。                                                                                                                                           | AoneD 页面结构未知、内部是否允许自动化未确认；人工协作版不依赖这两点，现在就能实现。                                                                                                                                    |
| D41  | 并发上限：全局 3；每个 Agent 配置默认 `codex` 2、`qoder` 1、`claude-code` 1、`gemini` 1、`aoned` 1；排队上限 50。等待审批的任务照样占槽位。                                                                                                                                                                                                                                                                                   | 一台笔记本同时跑三个 Agent 已经很重。                                                                                                                                                                                   |
| D42  | 审批**超时 60 分钟**：到点按“拒绝”回复 Agent，审批记为 `expired`（`security.approvalTimeoutMinutes` 可改）。Hub 重启时未决审批一律记为 `expired`。                                                                                                                                                                                                                                                                            | 审批不能无限期占着槽位；结果必须确定。                                                                                                                                                                                  |
| D43  | Codex 的 `clientInfo.name` 用 `agent_hub`，不做登记。                                                                                                                                                                                                                                                                                                                                                                         | 个人自用。                                                                                                                                                                                                              |
| D59  | ACP 审批只选“仅这一次”类选项：`allow_once` → “允许一次”，`reject_once` → “拒绝”，“拒绝并停止本轮”总是有；`allow_always` / `reject_always` **永远不选**，所以 ACP 任务没有“本会话允许”。只读任务里 Agent 请求退出计划模式（`switch_mode` 类权限请求）时，Hub 代为拒绝、不建审批，本轮以 `end_turn` 结束并发 `PLAN_EXIT_DECLINED` 提示（[adapter-acp.md](adapter-acp.md) §7）。                                                 | Claude Code 的 `allow_always` 会把允许规则写进项目的本地设置，在 Hub 之外长期生效；它“退出计划模式”的 `allow_always` 选项会切到 `auto` / `bypassPermissions` 等跳过审批的模式。只读任务允许退出计划模式就等于放弃只读。 |
| D60  | Hub **不调用** ACP 的 `authenticate` / `logout`。未登录按错误码（`-32000`、`401`、`403`）、错误文本和 claude-agent-acp 的扩展通知 `_auth/status_update`（`authStatus.kind === "none"`）识别；建会话期间收到未登录通知时 `startSession` 直接失败（`AGENT_AUTH_REQUIRED`），不等到发提示词。提示文案来自 profile 的 `authHint`，登录由人在终端里完成。                                                                          | `authenticate` 可能拉起浏览器登录、改写 Agent 自己的凭据文件，等于 Hub 接管了登录（违反“不接管各 Agent 的登录”）；实测 Claude Code 未登录时 `session/new` 照样成功，要到发提示词才报错。                                |

### 1.5 安全与 git

| 编号 | 决策                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | 理由                                                                                                                                                      |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D44  | 首次启动自动建一个默认桥接 token“本地郎（默认）”，scope 为 `tasks:read`、`tasks:write`，**不含 `approvals:decide`**；明文写入 `<AGENT_HUB_HOME>/bridge-token`（权限 `0600`），库里只存 SHA-256。设置页可以再建 token、给 token 加 `approvals:decide`（二次确认并写审计）、“轮换”默认 token（任务归属随之转移）；默认 token 被吊销后不会自动重建（[local-api.md](local-api.md) §2.2）。                                                                                                                                                                                                                                                                      | 审批默认留给人；本地郎读文件即可接入。                                                                                                                    |
| D45  | 桥接方创建的**可写任务强制使用 worktree**（不允许 `in_place`），**不需要人工确认**，直接排队。没有 `pending_confirmation` 状态。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | worktree 隔离、没有推送通道、命令执行仍要审批，风险已经可控；多一道确认会让本地郎的任务卡住。                                                             |
| D46  | 桥接方可以读 diff 和命令输出（包含在 `tasks:read` 里），diff 单次最多返回 512 KB，所有返回内容统一脱敏。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | owner 用本地郎的目的就是让它拿结果；截断和脱敏控制量与凭据。                                                                                              |
| D47  | 本地郎的接入方式：REST + `wait` 长轮询（单次最长 60 秒）为主，WebSocket 可选。v1 不提供 MCP server。本地郎必须作为本机进程调用 API；Bot 页面里的脚本拿不到任何 token，CORS 也不放行它的 origin。                                                                                                                                                                                                                                                                                                                                                                                                                                                            | 工具调用式的 Bot 最适合长轮询；把 token 交给网页等于交给该网页上的任何脚本。                                                                              |

| D52  | “应用到本地分支”：Hub 以用户的 git 身份把 worktree 里的改动提交到 `agent-hub/<shortId>`（`git commit --no-verify`），可选再 `git merge --no-ff --no-verify` 合并到原仓库当前分支；网页任务没有 worktree，只把本地分支快进到 AoneD 推上来的提交（D61）。**任何情况下都不推送。**                                                                                                                                                                                                                                                                                                                                                                             | Hub 生成的提交信息过不了仓库的 commitlint；这是本地任务分支上的提交，用户合并前可以自己改写。                                                             |
| D61  | 网页任务的 git 细节：远端任务分支拉到**镜像 ref** `refs/agent-hub/remote/<shortId>`（`fetch --refmap= --no-tags --no-write-fetch-head`），推送写**检查过的 URL** 而不是远端名，两者都不产生 `refs/remotes/*`；轮前 / 轮后快照和“应用到本地分支”只读镜像 ref、**不联网**（应用 = 把本地 `agent-hub/<shortId>` 快进到镜像 ref）；Hub **不删除** `internal` 上的任务分支，界面给出命令让用户自己删；Hub 的 `pre-push` 只在环境变量 `AGENT_HUB_PUSH_ALLOWED_HOSTS` 存在时放行（Agent 子进程没有这个变量），只允许推 `refs/heads/agent-hub/*`、禁止删除，不转发仓库自己的 `pre-push`（[web-agent.md](web-agent.md) §2.3、§4，[security.md](security.md) §3.3）。 | 不产生远端跟踪分支，Codex / ACP 任务的远端跟踪分支审计就不会误报；网络抖动不会让一轮失败，diff 与应用的内容始终一致；删除是不可恢复的远端操作，留给人做。 |
